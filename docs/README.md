# BusinessTable 文档导航

BusinessTable 是跨业务复用的 Vue 3 表格平台。报价管理是首个演示和旧版对照场景，`reference/legacy-v3.1/` 是只读参考。日常开发优先在 `development` 进行；`main` 保留为正式基线。

## 推荐阅读顺序

1. [项目背景](01-项目入门/01-项目背景.md)：目标、边界和技术基线。
2. [本地运行与接入](01-项目入门/02-本地运行与接入.md)：预览、安装及组件用法。
3. [当前状态](01-项目入门/03-当前状态.md)与[后续路线图](01-项目入门/04-后续路线图.md)：已完成能力、缺口与下一步。
4. [平台总体设计](02-架构与规范/01-平台总体设计.md)、[开发规则](02-架构与规范/02-开发规则.md)与[配置规范](02-架构与规范/03-配置与能力规范.md)：开始修改前确认职责和契约。
5. [业务模块](03-业务模块/README.md)：按任务核对演示业务和第二业务接入边界。

## 命名与维护

- 固定文档使用 `二位顺序号-中文名称.md`，按阅读顺序编号；工具入口 `README.md`、`AGENTS.md`、`CHANGELOG.md` 保留文件名。
- 版本记录使用 `04-版本记录/年-月/年-月-日-当日顺序号-主题.md`；正式发布才标注产品版本，文档整理不虚构版本号。
- 实施计划使用 `05-实施计划/年-月/年-月-日-主题.md`；验收放在 `06-验收记录/年-月/年-月-日-主题/README.md`，截图和原始报告可同目录保存。
- 当前状态和规范原位维护。每次升级独立记录，更新月份索引、分类索引和受影响的用法；历史记录保留当时结论，勘误说明日期与原因。
- 新文档必须能从本导航找到。移动文件时同步修复链接、图片、规则、工作流和代码中的引用，执行 `npm run audit:docs`。

详细约束见[文档编写与归档规则](02-架构与规范/04-文档编写与归档规则.md)。开发工作入口为仓库根目录的 [AGENTS.md](../AGENTS.md)。
