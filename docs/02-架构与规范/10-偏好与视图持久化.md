# 偏好与视图持久化

“点击应用”“保存到浏览器”“保存命名视图”“写入后台”是不同动作。接入时先决定保存的对象和责任方，再选择适配器。公开类型见 [types.ts](../../src/types.ts)、[config/types.ts](../../src/config/types.ts)，存储状态不要塞入业务行数据。

## 保存对象对照

| 对象 | 内容 | 入口与格式 |
| --- | --- | --- |
| 本地定义 | 字段、功能、能力、默认值、布局 | `TableDefinition`，schemaVersion: 3 |
| 直接入口个人配置 | 列、页大小、外观/动作/工具布局、条件标记 | `TableConfig`，schemaVersion: 1；Persistence |
| 配置入口个人差量 | 相对合法代码基准的偏好 | `PreferenceV3`，kind: business-table-preference，schemaVersion: 3 |
| 命名视图 | 查询、Search 已应用值、排序、列差量、pageSize、可选布局/标记 | ViewConfig[] 或 business-table-views 封套，schemaVersion: 3 |
| 筛选方案 | columnFilters + filterGroup | business-table-filter-plans，**version: 1**，不是 schemaVersion |
| 导出方案 | 导出字段、顺序、格式等选项 | ExportPreset[]，通过 savePresets 适配 |
| 查询区 UI 偏好 | advanced、searchVisible | useTableControls 独立适配器 |
| 临时状态 | 编辑草稿、展开项、选区、请求 loading、无效数字输入 | 不写入正式配置或 View |

版本号属于各自协议，不能把所有对象统一改成 3。设置历史不在本项目范围内。

## BusinessTable：Persistence

完整局部声明，可与最小表格一起使用：

```ts
import { createLocalStoragePersistence } from '@company/business-table'

const tableKey = 'tenant-01.user-01.assets'
const persistence = createLocalStoragePersistence('my-product')
```

在表格上绑定 `:table-key="tableKey" :persistence="persistence"`，并开放需要的设置。保存键是 `prefix:tableKey`。仅有 tableKey 不会自动保存普通列偏好；直接入口的 persistence 默认是 null。筛选方案默认本地保存属于另一条协议，见下文。

后台适配可使用 `createHttpPersistence('/api/table-config')`，其现有 HTTP 约定是：

| 请求 | 响应/意义 |
| --- | --- |
| GET `/api/table-config?tableKey=...` | 200 返回 TableConfig；404 表示无配置，load 返回 null |
| PUT `/api/table-config`，body 为 `{ tableKey, config }` | 2xx 表示保存成功，非 2xx 抛错 |

这是辅助函数要求的协议，不是仓库已有 API。需要鉴权 Header、租户路由或封套响应时，使用自定义 `Persistence` 或注入 fetcher；load 接收可选 signal，必须透传。完整配置应与 tableKey 一起保存，不只保存当前可见列。

## ConfiguredBusinessTable：PreferenceV3

完整接线见 [ConfiguredTable.vue](../03-业务模块/01-接入示例/ConfiguredTable.vue)。流程是：

1. 宿主加载对应租户/用户/表格的偏好，保留 unknown 输入交给配置解析器。
2. 通过 `preference` 传入，Definition/Remote/Capability 解析后应用合法差量。
3. 通过 `savePreference(next): Promise<void>` 等待后台实际写入成功。
4. 保存成功后，`preferenceChange(next)` 通知宿主同步已提交值。

**不要只在 `preferenceChange` 中异步保存然后声称组件已经确认后台成功**：事件只是通知，没有回传 Promise 的事务确认。显式传 savePreference 才参与 Runtime 的保存成功/失败流程。

Preference JSON 示意：

```json
{
  "kind": "business-table-preference",
  "schemaVersion": 3,
  "tableKey": "tenant-01.user-01.assets",
  "columns": { "name": { "width": 260, "order": 1 } },
  "pagination": { "pageSize": 20 },
  "presentation": { "appearance": { "density": "compact" } }
}
```

不要自行把它改成 TableConfig 或 VXE 内部对象。旧版协议迁移、坏 JSON、失效字段由现有解析器检查并产生 diagnostic；业务后台仍需版本和权限校验。初次后台读取失败时，不应把失败当成“没有偏好”并允许自动覆盖，示例采用重试读取后再进入编辑界面。

## 应用、取消与失败

- 设置编辑器维护草稿；应用经过校验、能力守卫和保存，再发布正式配置。
- 应用失败保留原有正式设置，并允许修正/重试；非法数字草稿不会进入 Preference/View。
- 命名 View 不会被一次设置应用自动覆盖；用户需要更新视图或另存为视图。
- Runtime 的写队列只协调当前实例写入，不提供跨标签页、跨设备互斥。
- 只读会保留已有合法值，隐藏/关闭和只读不是同一种状态；后台更新权限后每次写入仍会重新检查。

## 命名视图

`views` 属性用于提供视图及切换；完整创建、改名、设默认、重排、删除使用公开的 `createViewsRuntime` + `ViewsPanel`，完整示例见 [ViewsTable.vue](../03-业务模块/01-接入示例/ViewsTable.vue)。两种入口不要同时维护两份列表。

| Runtime 入口 | 作用 |
| --- | --- |
| `createViewsRuntime({ tableKey, initial, apply, save })` | 读取初始集合，统一命令和保存事务 |
| `apply(id)` | 调用宿主 apply(ViewConfig)，恢复表格状态 |
| `saveAs(name, snapshot)` | 新建，返回稳定 ID |
| `update(id, snapshot)` / `rename(id, name)` | 更新快照 / 改名 |
| `setDefault(id)` / `move(id, offset)` / `remove(id)` | 默认、顺序、删除 |
| `BusinessTable.viewSnapshot()` | 取得已应用查询与布局快照，不拼装搜索草稿 |

View 保存 pageSize，不保存当前 page=7。`search.values` 按稳定搜索项 ID 保存；查询层仍分开 filters、columnFilters、filterGroup。系统视图清查询并保留当前个人布局；系统/只读视图不能修改。工具栏布局只有 followView 为 true 才进入相应视图快照。

推荐保存封套 `{ kind: 'business-table-views', schemaVersion: 3, tableKey, views }`。`readViews` 也接受数组，但封套便于检查所属表格。读取失败需要提示与重试，不把失败结果作为空数组覆盖原存储。

配置入口没有公开 `viewSnapshot/applyView` 的同名引用方法；使用完整管理示例时选直接入口或按当前公开 Context 集成，不通过私有子组件引用绕过边界。

## 筛选方案与 UI 偏好

Filters 开启且 tableKey 非空时，方案默认保存在 LocalStorage。传 `filterPlanPersistence: null` 关闭方案管理；传自定义 `FilterPlanPersistence` 接后台，load 返回 unknown，save 保存完整 `FilterPlansEnvelope`。

封套为 `{ kind: 'business-table-filter-plans', version: 1, tableKey, plans }`。方案载入改变草稿，应用才查询；首次操作需要成功 load，读取失败不会以空方案覆盖原数据。Custom/Headless 使用 `FiltersContext.plans` 和 `readPlan/apply`，具体示例见[本地运行与接入](../01-项目入门/02-本地运行与接入.md#自定义与-headless-筛选方案)。

`useTableControls` 仅保存 advanced/searchVisible 两个布尔值，不保存临时多选栏；它和 View 有不同用途。导出方案也使用独立适配器，不与个人布局键混写。

## 账号隔离、升级和冲突

- 本地键至少区分产品、租户、用户和表格。账号切换时重建对应页面实例/键，避免把上一账号偏好带入下一账号。
- 服务端以登录会话决定可访问范围，不信任请求中的 tableKey 可代表任何用户。
- 删除/更改列或搜索项前评估旧 ID；改标签可保留 ID，业务含义变化需迁移，不复用旧 ID 指向无关字段。
- Definition、Preference、View、筛选/导出方案分别迁移和备份，不手工大范围清空 localStorage 作为升级方式。
- 并发编辑推荐业务 API 使用版本号或 ETag 发现冲突。当前平台不内置服务端版本冲突协议，遇到冲突应 reject、提示重新读取，不能覆盖未知更新。

## 显式默认值

Presentation 偏好与视图只保留输入中显式合法的字段，包括 false、空字符串及等于平台默认值的项。不能先补齐平台默认再删除默认项，否则业务基线为 true 时会丢失用户显式关闭。底部汇总关闭使用 `appearance.summaryEnabled:false`；稳定列标识存入 `summaryColumn`，不存显示标题。
