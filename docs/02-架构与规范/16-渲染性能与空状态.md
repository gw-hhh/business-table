# 渲染性能与空状态

## 选择分页和渲染方式

分页决定读取哪些数据，虚拟滚动决定同时绘制多少行。关闭分页不会自动启用虚拟滚动；远程完整读取仍须满足 `readAll` 与 `unpagedLimit` 协议。

BusinessTable、BusinessTableGrid 使用 `rendering`，ConfiguredBusinessTable 使用 `definition.rendering`。这些选项属于宿主渲染环境，不进入 Preference 或 View，也不接受远端覆盖。

| 字段 | 默认 | 说明 |
| --- | --- | --- |
| `height` | 未声明 | 正数像素，固定表格高度（包含表头），优先于 fill 和 maxHeight |
| `maxHeight` | 未声明 | 正数像素，随内容增长至此高度；没有固定 height/fill 高度时生效 |
| `virtualRows` | false | true 使用 VXE 原生纵向窗口；也可传下列对象 |
| `virtualRows.enabled` | 对象声明时 true | false 关闭 |
| `virtualRows.threshold` | 100 | 非负整数，超过此行数启用；0 表示任意行数；上限 100000 |
| `virtualRows.overscan` | 5 | 窗口外缓冲行数，0–100 |

虚拟滚动需要有效 height、maxHeight，或 fill 模式已经测得正数高度。没有高度约束时保持普通渲染，避免把整页当虚拟视口。它保留列的换行、自动行高和固定列；没有强制 `showOverflow` 截断富文本。

```vue
<BusinessTable
  :columns="columns" :data="rows"
  :pagination="{pageSize:500,pageSizeOptions:[100,500,1000]}"
  :rendering="{height:520,virtualRows:{threshold:100,overscan:5}}"
/>
```

上例为局部配置片段。完整公开包示例见 [RenderingTable.vue](../03-业务模块/01-接入示例/RenderingTable.vue)。`/?example=performance` 可比较 1000/10000 行、完整/虚拟渲染和分页；请优先用实际业务字段、模板和设备实测。

## 空状态插槽

三个表格入口都支持 `#empty="context"`。默认显示中文状态文字；平台不会自动删除查询或提供假业务动作。业务需要“新建”时自行提供业务按钮。

| context | 内容 |
| --- | --- |
| `reason` | loading、error、no-results、empty，按此优先级 |
| `query` | 当前已应用 Query 的独立快照，修改它不会提交查询 |
| `error` | Runtime 的错误文字 |
| `reload()` | 重试当前查询，不清除条件 |
| `clearQuery()` | 按既有搜索 resetBehavior 清理用户查询条件 |

`no-results` 仅表示当前有效查询带有条件且没有行，不能据此断言后台数据库非空。服务器强制范围/权限条件应保留在 DataSource 适配器中，不能放入可清除的用户条件。草稿未提交不改变当前结果原因。VXE 可能调用空状态插槽进行隐藏区域测量，插槽应保持纯渲染，不在渲染中发请求或提交命令。

## 性能验证与边界

Runtime 为可完整追踪的响应式定义缓存签名；普通对象、浅响应式或含原始可变子节点的输入保留即时检查，兼容原地修改。翻页缓存键只读取影响关键词和映射排序的列信息，不序列化文字样式等无关元数据。关闭自动查询时不会订阅草稿签名；条件标记每行计算并缓存匹配列 ID，单元格不重复遍历列。

`tests/e2e/rendering-performance.spec.ts` 检查 DOM 行数有界、多行行高、滚动至末行、选择保留和空状态恢复，同时输出浏览器时间样本。`npm run benchmark:runtime` 仅测查询/翻页计算，不能替代浏览器渲染测量。机器负载、开发预加载、字段复杂度会影响时间，不把单次结果写成性能承诺。
