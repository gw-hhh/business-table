# 文档编写与归档规则

## 分类与阅读

所有项目说明从 [docs 总导航](../README.md)进入。01 项目入门介绍背景、运行和现状；02 维护架构与规范；03 维护业务适配；04 保存每次版本变化；05 保存实施计划；06 保存真实验收；07 保存参考与过期材料。每个分类和月份目录均维护 README 索引。

## 文件名称

- 固定文档使用 `二位顺序号-中文名称.md`，序号代表阅读顺序；已有编号不随每次修改重排。
- 版本说明放在 `04-版本记录/年-月/年-月-日-当日顺序号-主题.md`，同日从 01 递增。正式版本号仅在真实发布时添加，不因整理文档而升版本。
- 计划放在 `05-实施计划/年-月/年-月-日-主题.md`。
- 验收放在 `06-验收记录/年-月/年-月-日-主题/README.md`；截图、原始日志和报告与对应说明放在一起，说明证据来源、提交及保存期限。
- `README.md`、根 `AGENTS.md`、`CHANGELOG.md` 和机器报告保留约定文件名；中文标题与说明保持简洁，类型名、命令、技术名称不强行翻译。

## 内容写法

先写结论和适用范围，再写必要背景与操作。一个段落说明一件事。区分设计目标、当前能力和历史结果；不要用“已完成”覆盖未执行验证或待接入的后台协议。规范只存一份事实源，其他文件用链接引用，避免反复复制整套规则。

平台能力归属 Feature/Runtime/Config/Persistence；业务文档说明数据、字段和动作。不要照搬参照项目的外壳、业务或数据库约束。涉及视觉、接口、配置、持久化和失败处理的改变应说明兼容影响与验证范围。

## 每次升级清单

1. 更新当前状态和受影响的用法、配置、架构或业务说明。
2. 采用[版本说明模板](../04-版本记录/00-版本说明模板.md)新增独立记录，关联计划和验收；更新月份索引和版本总索引。
3. 历史记录保留发生时的结果。勘误追加日期和原因；过期流程归入参考与归档，并指向现行规则。
4. 移动或改名时修复仓库内所有可维护的文档、图片、脚本和工作流引用。原始交付证据与只读参考文件不改写，归档索引说明旧路径的历史用途。
5. 执行 `npm run audit:docs`。它检查本地链接、标题锚点、中文编号、月份和文档可达性；外链访问权限和实时可用性需按任务单独确认。
6. 代码变更或集成执行完整 `npm run verify:release`，准确区分本地、远端 CI、用户体验与实际发布状态。
