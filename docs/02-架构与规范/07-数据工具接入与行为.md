# 数据工具接入与行为

当前 `development` 提供条件标记、分组汇总、记录对比和区域选择。四项默认关闭，须分别在 `features` 中开启。设置历史已按用户本轮决定排除，不提供入口、状态或持久化协议。本说明是四项工具的配置与运行时契约；报价字段和示例数据见[报价演示模块](../03-业务模块/01-报价演示模块.md)，实际验证见[本批验收](../06-验收记录/2026-09/2026-09-23-剩余数据工具对齐/README.md)。

## 开启与状态归属

直接使用 `BusinessTable` 时，通过 `features.conditionalFormatting`、`features.grouping`、`features.compare`、`features.rangeSelection` 开启工具，并分别传入同名定义属性。`ConfiguredBusinessTable` 使用 `definition.features` 与 `definition.conditionalFormatting` 等属性。定义使用稳定 `Column.id` 选择字段；实际行读取仍使用列的 `field`。四项默认界面按交互加载，也支持 `mode: 'custom'` 的 `#conditional-formatting`、`#grouping`、`#compare`、`#range-selection` 插槽和 `mode: 'headless'` 的 Context。程序入口为 `openDataTool(name)`，Headless 可使用 `activateFeature(name)`。

`details.allowedItems` 使用列 ID 白名单；远端 `features.<工具>.details.allowedItems` 只能进一步收窄。远端也可关闭或禁用已开启工具，不能开启本地未声明的工具。`entry: false` 只隐藏默认入口，宿主可在真实工具菜单调用 `openDataTool`。显式 `disabled: true` 时保持可查看的已有结果或标记，阻止相关编辑命令；区域选择只读时不能启动。Gate 关闭时不读取该工具定义或加载界面；条件标记 Gate 开启后，即使从未打开编辑抽屉，也会根据合法规则标记行。

```ts
import type {ConditionalFormattingDefinition,GroupingDefinition,CompareDefinition,RangeSelectionDefinition} from '@company/business-table'

const features = {
  conditionalFormatting:{enabled:true,entry:false},
  grouping:{enabled:true,entry:false},
  compare:{enabled:true,entry:false},
  rangeSelection:{enabled:true,entry:false},
}
const conditionalFormatting:ConditionalFormattingDefinition = {allowedColumns:['amount']}
const grouping:GroupingDefinition = {groupColumns:['status','owner'],defaultGroups:['status'],summaryColumns:[{columnId:'amount'}]}
const compare:CompareDefinition = {searchColumns:['name'],labelColumns:['name'],recordLabelColumn:'name',differenceColumns:[{columnId:'amount'}]}
const rangeSelection:RangeSelectionDefinition = {summaryColumns:[{columnId:'amount',label:'金额'}]}
```

## 条件标记

每条 `ConditionalRule` 为 `{id,condition,enabled,label,color,background}`。`id` 稳定且唯一；`condition` 是类型化 `FilterConfig`，最多保存 30 条。规则按顺序匹配，首条启用且命中的规则决定行标记。颜色使用六位十六进制；提示文字最多 24 个字符。条件比较行的**原值与原类型**，数字字符串不会当成数字；列显示缩放和列筛选开关不改变标记含义。标记只影响展示，不改变 Query、排序、分页或业务记录。

`ConditionalFormattingDefinition` 可声明 `defaultRules`、`allowedColumns`、`defaultColumn`。规则优先级为当前非系统 View 的 `conditionalFormatting` → 个人 `TableConfig.conditionalFormatting` → 定义的 `defaultRules`。显式空数组表示清空这一层，不回退到下一层。系统 View 清查询并保留当前布局和标记。View 恢复和每次写入都重新检查当前列与 `allowedColumns`；无效持久化值产生诊断并回退，不让失效字段继续生效。显式只读保留已有合法标记。

直接入口的 `Persistence.save(tableKey, config)` 在**同一次完整配置保存**中写入可选 `conditionalFormatting`；保存失败时正式规则和当前 View 覆盖不变。`PreferenceV3` 与 `ViewConfig` 均新增同名可选字段，版本号不变，旧数据缺失时仍可读取。配置值是数据，不保存函数、VXE 对象或编辑草稿。

配置入口可传入可等待的 `savePreference`：

```vue
<ConfiguredBusinessTable
  :definition="definition" :preference="preference"
  :save-preference="async next => { await preferenceApi.save(next) }"
  @preference-change="next => { preference = next }"
/>
```

宿主负责先读取 `preference` 并传回组件。提供 `savePreference: (value: PreferenceV3) => Promise<void>` 后，Runtime 等待保存成功再发布设置和标记；失败保留原状态并报告错误。原有 `preferenceChange` 事件仍用于通知宿主最新差量；**仅使用该事件没有外部保存成功的确认**，不能据此宣称远端原子持久化。服务端账号范围、权限和并发版本冲突仍由业务适配器处理。

## 分组汇总与记录对比

两项工具共用只读报告 Context，按当前完整 Query 调用 `readRows('query')`。本地 `data` 使用同一查询规则；远程 `DataSource` 必须提供 `readAll(query, {limit,signal})`，上限 10000 条。接口缺失、超限或失败时显示错误并允许重试，不用当前页冒充完整结果。查询、列、定义或面板生命周期变化会取消旧请求并忽略迟到结果。`allowedItems` 收窄可用列；报告不修改原表的排序、分页或选择。

`GroupingDefinition` 以 `groupColumns` 声明可分组列、`defaultGroups` 声明初始层级，最多两级；`detailColumns` 与 `summaryColumns` 决定明细及数值合计列，可设置标题和导出名。分组键按原值类型区分；合计用十进制/BigInt 处理原始数值，显示通过列解释器生成。分组可展开、收起并导出汇总。

`CompareDefinition` 可声明搜索列、候选标签列、记录名称列、差额列和导出名称。从完整查询结果选择 2–4 条记录，可指定基准、只看不同项并导出对比。候选列表最多直接显示 100 条，超过时需输入关键词缩小范围；差额使用原始数值计算，展示值仍遵守列格式。两项 XLSX 写入模块仅在点击导出时动态加载；大数据或服务端导出需要业务接口另行提供。

## 区域选择

区域选择只覆盖**当前页的可见数据列**，与业务行选择相互独立，不进入 Preference、View 或 Query。可用鼠标拖动、方向键和 Shift 扩选；关闭、查询/页码/数据/列布局变化时清空。复制生成带转义的 TSV；浏览器拒绝剪贴板写入时显示可手动复制的内容。`RangeSelectionDefinition.summaryColumns` 可指定统计列；选区计数、合计、平均、最小和最大基于原始数值计算，再使用列格式显示。

## 验收边界

当前仓库没有实际业务后台接口。`DataSource.readAll`、Preference 写入、权限收窄和多客户端冲突需由接入方提供并在真实环境验证。本地单测、模拟数据源和 Chromium 场景只证明对应的本地行为；完整发布检查、旧版视觉对照及用户体验结论以[本批验收](../06-验收记录/2026-09/2026-09-23-剩余数据工具对齐/README.md)的最终实测记录为准。
