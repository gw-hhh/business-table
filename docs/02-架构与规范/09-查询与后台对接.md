# 查询与后台对接

本页说明前端实际 `DataSource<T>` 契约和建议的 HTTP 映射。`/api/assets/*` 路由是教学示例，业务后台需要自行实现；前端类型检查不能证明 SQL、鉴权和数据范围正确。

完整适配器：[asset-source.ts](../03-业务模块/01-接入示例/asset-source.ts)。配套 Vue：[RemoteTable.vue](../03-业务模块/01-接入示例/RemoteTable.vue)。平台类型来源：[types.ts](../../src/types.ts)。

## 三个接口各负责什么

| 接口 | 必需性 | 返回 | 使用场景 |
| --- | --- | --- | --- |
| `query(query)` | 必须 | Promise<{ rows: T[]; total: number }> | 服务端分页 |
| `readAll(query, { limit, signal })` | 按功能需要 | Promise<T[]> | 全查询选择、分组/对比、完整导出、无 options 时的数据候选项 |
| `options(column, query, { search, signal, values? })` | 远程候选项需要 | Promise<FilterOption[]> | 筛选选项、计数、已选原值标签回查 |

如果只是本地全量数组，传 `data` 即可。不要只取远端一页传入 data，否则组件会把这一页当成全部数据。

## Query 请求字段

| 字段 | 含义 | 后台处理 |
| --- | --- | --- |
| page / pageSize | 页码从 1 开始 / 每页条数 | 返回当前页及筛选后的 total |
| keyword | 关键词 | 业务适配器决定可搜索字段；不同于某个字段 contains |
| filters | 基础条件，包含 Search 投影 | 按 AND 执行一次 |
| columnFilters | 列筛选条件 | 按 AND 执行一次，不能遗漏 |
| filterGroup | 嵌套 and/or 条件树 | 保留组层次与括号 |
| sorts | 有序排序规则数组 | 数组顺序代表优先级，建议增加稳定主键兜底排序 |
| viewId | 当前视图标识 | 仅标识，不代替实际查询条件，也不能当权限凭证 |
| signal | AbortSignal | 传给请求客户端；不发送到 JSON |

总体关系是：业务授权数据范围 AND keyword AND filters AND columnFilters AND filterGroup。授权范围由服务端添加，不由用户配置决定。

下面是合法请求数据示意：

```json
{
  "page": 1,
  "pageSize": 20,
  "keyword": "传感器",
  "filters": [{ "field": "status", "operator": "eq", "value": 1 }],
  "columnFilters": [{ "field": "amount", "operator": "gte", "value": 1000 }],
  "filterGroup": {
    "logic": "or",
    "rules": [
      { "field": "name", "operator": "contains", "value": "温度" },
      { "field": "name", "operator": "contains", "value": "压力" }
    ]
  },
  "sorts": [{ "field": "amount", "order": "desc" }]
}
```

分页响应：

```json
{
  "rows": [{ "id": "A-001", "name": "温度传感器", "status": 1, "amount": 1280 }],
  "total": 1
}
```

查询失败应 reject，不能伪装成空数据成功。Runtime 保留上次数据并显示错误，可刷新重试。total 导致页码越界时，会补查最后有效页；总数为 0 时收敛到第 1 页。

## 操作符与类型

| 操作符 | value 形状 | 注意 |
| --- | --- | --- |
| eq / ne | 标量 | 数字 1、字符串 "1"、布尔 true 按类型区分 |
| contains / starts | 字符串 | 服务端保持与本地约定一致的字符串比较语义 |
| in / notIn | 标量数组 | 保留每项类型，不拼接 SQL 字符串 |
| gt / gte / lt / lte | 数值，或日期编辑器允许的日期值 | 字段类型与操作符双重检查 |
| between | 两个端点的数组 | 数值或有效日期范围；包含边界 |
| empty / notEmpty | 通常为 null | 由操作符表示空值判断，不是字符串 "null" |
| nextDays / pastDays | 非负整数天数 | 日期相对范围；时区、当天和边界须对照本地实现验收 |

不同编辑器仅允许其中一部分；例如列枚举使用 in/notIn，Search 单选通常使用 eq。列 `filter.operators` 再收窄范围。后端应按字段白名单翻译到参数化查询，不直接执行 field 或配置文本。

日期本地语义及限制见[筛选实现](../../src/runtime/filter.ts)。真实后台要明确时区、大小写、空字符串/空值的处理并做对照；不要依赖数据库默认规则碰巧相同。

## 原值、显示标签与单位

候选项如下，摘要显示“已确认”，查询仍发数字 1：

```json
[
  { "value": 0, "label": "草稿", "count": 8 },
  { "value": 1, "label": "已确认", "count": 12 }
]
```

恢复视图时，当前候选列表可能没有选中的值。组件会调用 options 并传 `values: [1]`；接口应把这些已选原值对应的标签返回，即使不在当前页或关键词候选内。不存在/失效值可以查不到，但不能把 1 改为 "1"。失败时摘要回退显示原值，正式条件不被改写。

`SearchDefinition.options` 是代码传入的搜索选项；`DataSource.options` 用于列/组合筛选。不要以为实现后者会自动给所有 Search 下拉框装载选项，搜索选项应由宿主加载后传入，或通过注册的自定义 Search 扩展。

数字筛选的 `value` 已换算为业务原值；`unitFactor` 记录编辑与显示基准，不要在后台再次乘一万元或除 100。`column.filter.inputUnit` 声明“元”“件”等原值单位，不猜测数据库金额是分还是元。显示缩放与实际查询值相互独立。

## readAll 完整读取

示例 HTTP 请求为 `{ query, limit }`。后台忽略页码分页限制，执行当前查询和排序，返回完整行数组。前端读取上限是 10000 条；后台应检测超过上限并报错，不能悄悄截断成 limit 条让前端误以为已经读全。

- 查询范围：保留当前条件与排序。
- 全部范围：调用方已按范围构造查询；适配器按收到的 query 执行，不在内部偷偷合并旧搜索值。
- 返回行保持原始类型；不要为了导出先把金额转成带逗号的文本。
- 超出浏览器读取范围的导出要接服务端导出任务；当前 DataSource 没有内置“几十万条分页循环拉取”模式。

## 请求生命周期与失败

Runtime 使用 AbortController 和请求序号，取消并忽略迟到结果。把 query.signal 或 options.signal 传给 fetch；不要 catch 后把 AbortError 伪装成查询成功。Provider 替换和组件卸载后，旧响应不能写回。

建议 DataSource 对象在 setup 创建一次。`queryChange` 用于观察快照，已经提供 dataSource 时不要再在事件处理里重复发同一请求。快速查询、翻页、切视图都应只保留最后一次结果。

## 后台联调清单

1. 校验非 2xx、损坏 JSON、缺少 rows/total、错误类型都能显示错误并重试。
2. 连续查询 A/B，让 A 晚返回，仍显示 B；取消请求实际传到网络层。
3. 同时开启基础、列、组合条件，核对总数、分页与导出的一致性。
4. 数字 1 与字符串 "1"、0/false/null、万元/百分比、日期边界分别核对。
5. 恢复旧视图后 options 按 values 回查标签；找不到时仍保留原值。
6. readAll 缺失、失败、超限时显示错误；不返回部分结果冒充完整结果。
7. 服务端独立检查账号权限、字段白名单、数据范围及查询复杂度。
