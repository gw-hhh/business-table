# 组件组合与分页

`BusinessTable` 保留完整默认布局；需要把搜索、工具、表体和分页放到不同区域时，在 Vue `setup` 中创建一个 `useTableRuntime`，把同一实例交给各组件。查询、分页、列配置、选择和失败状态由 Runtime 管理，业务页面提供数据、字段及动作。

完整可复制示例为 [ComposedTable.vue](../03-业务模块/01-接入示例/ComposedTable.vue)。运行 Demo 后访问 `/?example=composition`，可操作两个各自独立的表格实例；本批实际验证结果见[验收记录](../06-验收记录/2026-09/2026-09-29-组件组合与交互基础升级/README.md)。

## 入口与样式

| 入口 | 用途与边界 |
| --- | --- |
| `@company/business-table` | 保留 BusinessTable、ConfiguredBusinessTable、插件和既有公开导出；同时提供本轮新增组件与 Runtime |
| `@company/business-table/runtime` | ESM 状态与命令入口，导出 `useTableRuntime` 及对应类型、查询/视图基础 API；不导入 Vue 组件、VXE 或 CSS |
| `@company/business-table/components` | ESM 组件入口，提供表体、搜索、工具和分页；设置、视图、编辑器及导出对话框按组件使用加载 |
| `@company/business-table/style.css` | 表格及共享界面样式 |

组件宿主仍需按[安装教程](../01-项目入门/06-逐步接入教程.md)加载 `vxe-table/lib/style.css` 和 `@company/business-table/style.css`。仅使用 Runtime 的模块不需要导入样式。根入口兼容原有插件接法；UMD 继续提供单文件分发，ESM 子入口负责按模块消费。

## 创建和共享实例

```ts
import {useTableRuntime} from '@company/business-table/runtime'
import {BusinessTableGrid, SearchRegion, SearchToggle, TablePagination, TableTools}
  from '@company/business-table/components'

const table = useTableRuntime({
  tableKey: 'assets.list', rowKey: 'id',
  data: [{id: 1, name: '设备 A'}],
  columns: [{id: 'name', field: 'name', title: '设备名称', sortable: true}],
  pagination: {pageSize: 10, pageSizeOptions: [10, 20, 50], variant: 'full'},
  searchDefinition: {
    items: [{id: 'name', label: '设备', kind: 'text', field: 'name', operator: 'contains'}],
  },
})
const search = table.searchContext()
const tools = [{id: 'refresh', label: '刷新', handler: () => table.reload()}]
```

```vue
<SearchToggle :panel="table.searchPanel" />
<SearchRegion :panel="table.searchPanel" :context="search" />
<TableTools :tools="tools" />
<BusinessTableGrid :runtime="table" title="设备列表" />
<TablePagination :runtime="table" />
```

上面两段合并到同一个 Vue SFC 的 `<script setup>` 与 `<template>`。输入会变化时使用响应式对象或 getter，例如 `get data() { return props.rows }`、`get columns() { return props.columns }`；不要在创建时复制一份随后失去联系的 props。组合式函数使用 Vue 生命周期，应在组件 setup 内调用。每个独立列表创建自己的 Runtime 与稳定 `tableKey`，不把实例放成模块级单例。

| 组件 | 主要参数与职责 |
| --- | --- |
| `BusinessTableGrid` | `runtime` 必填；可传 title/fill/loading/cellRenderer/columnHeader；提供 cell、columns 插槽与 cellAction 事件 |
| `SearchRegion` | `panel`、`context` 必填；默认显示 TableSearch，默认插槽接收 `{context, panel}`，可放外置自定义表单 |
| `SearchToggle` | 接收 `panel`，通过 aria-controls/aria-expanded 关联查询区域；插槽可替换按钮文字 |
| `TablePagination` | 接收 `runtime`，读取同一页码/总数/配置；summary 插槽替换总数区域，默认插槽接收 `{context}` 自绘分页控件 |
| `TableTools` | 共享 ToolStrip 的公开名称；接收 tools/layout 等工具参数，handler 显式调用 Runtime 或业务动作 |

Grid 提供表体、选择及基础表头交互；完整 Feature Gate、设置入口、筛选面板、数据工具与行操作的默认组合继续由 BusinessTable 提供。独立组合不会自动创建这些面板；需要时由宿主接入相应公开组件和上下文。

Runtime 中 `rows/total/page/pageSize/busy/error` 等为 Ref，脚本中读取 `.value`。公开命令包括 `reload()`、`goPage(page)`、`setPageSize(size)`、`setQuery()`、`clearQuery()`、`applyView()`、`getState()`、`getSelectedRows()` 与 `readRows()`。查询、选择、列与设置仍使用现有校验和失败路径。`useTableRuntime(input, events)` 的第二个参数可接收 queryChange、paginationChange、configChange、viewChange、selectionChange 和 diagnostic。

## 搜索区域与草稿

`searchDefinition` 声明查询字段，`searchPanel` 管理查询区界面。直接 BusinessTable 仍需要开启 `features.search`；ConfiguredBusinessTable 使用 `definition.search` 和 `definition.searchPanel`。独立 Runtime 显式传入 searchDefinition 后启用搜索区域。

| SearchPanelOptions | 默认与行为 |
| --- | --- |
| `regionId` | 未传时为每个组件实例生成唯一 ID；手动指定时须保证页面内唯一 |
| `defaultVisible` | 默认 true，初始化时显示搜索区 |
| `toggleButton` | 默认不显示内置开关；true 时 BusinessTable 显示 SearchToggle。手动放置 SearchToggle 不受此字段限制 |
| `autoSubmitMs` | 默认手动提交；传入 0–10000 毫秒启用自动提交。负数或非有限值不启用，超过 10000 时按 10000 处理；0 在下一次计时器任务提交 |

`SearchRegion` 隐藏时保留挂载的表单和搜索草稿。`panel.show()/hide()/toggle()` 控制整个区域，`panel.setAdvanced(boolean)` 单独控制高级条件展开，两者互不替代。Search Context 的 `setValue` 修改草稿，`submit/reset` 复用正式查询命令；手动提交、重置、切换实例/定义和卸载会取消旧自动提交计时器。

`searchPanelPersistence` 只保存界面偏好，接口为同步 `load(tableKey): unknown` 和 `save(tableKey, {searchVisible, advanced}): void`。读取可返回对象、JSON 文本或空值；非空数据的两个字段都必须是 boolean。读取或保存失败通过 diagnostic 报告，保留可操作界面。适配器负责账号/页面隔离，该偏好不进入 Query、Preference 或 View；原有 `useTableControls` 继续兼容。

## 分页显示和分页执行

`pagination.visible: false` 隐藏分页栏，查询仍按页执行；可把 TablePagination 放在另一区域或用命令翻页。`pagination.enabled: false` 关闭分页，页码固定为 1，本地返回完整筛选结果；远程必须有 `readAll` 完整读取能力。

| 分页字段 | 默认与作用 |
| --- | --- |
| `page` | 初始为 1；后续属性变化可请求对应页，Runtime 会纠正越界页码 |
| `pageSize` / `pageSizeOptions` | 默认 20；直接 Runtime/BusinessTable 默认选项为 10、20、50、100，配置入口默认 20、50、100；页大小必须在有效选项中 |
| `enabled` / `visible` | 均默认 true；分别控制是否分页、是否绘制分页栏 |
| `hideOnSinglePage` | 默认 false；true 且只有一页时隐藏分页栏 |
| `showTotal` / `showPageSize` | 均默认 true；控制总数区域和页大小选择 |
| `showPageNumbers` / `showJumper` | 未声明时由 variant 决定，full 显示、simple 隐藏；显式布尔值优先 |
| `align` | 默认 right，可选 left/center/right，控制分页按钮区域对齐 |
| `variant` | simple/full；独立组件默认 simple，BusinessTable 的 fill 模式默认 full，显式 variant 优先 |
| `unpagedLimit` | 远程关闭分页时默认 10000，合法范围 1–10000；直接 Runtime 对超上限值限制为 10000，配置入口会诊断非法值 |

总数由本地查询结果或 DataSource 的返回值计算；`pagination.total` 不作为外部总数输入。用户页大小仍通过既有配置/Preference/View 保存；显示开关和查询区临时状态不会混入页大小偏好。

BusinessTable 提供 `#pagination="{runtime}"` 插槽替换默认分页，可组合自定义按钮。分页命令沿用取消旧请求、丢弃迟到结果和总数缩小后纠正页码的流程；`paginationChange` 只报告 `{page, pageSize}`。

## 远程关闭分页

`DataSource.readAll(query, {limit, signal})` 必须返回当前条件下的完整结果。返回数量超过上限或没有 readAll 时，Runtime 显示错误并保留原结果；不能把超大 pageSize 或截断数组当作完整读取。若后台有更多数据，适配器必须显式拒绝，数组长度本身无法证明后台没有截断。查询信号与迟到结果保护与普通分页一致，详见[后台对接](09-查询与后台对接.md)。

本地分页使用缓存复用相同数据和条件的筛选/排序结果，翻页只切片；数据、查询条件或列解释变化会失效，`reload()` 强制重算。条件标记按当前页行计算后复用。性能测量属于本批验收，文档不把这些实现直接表述为未测量的提升比例。

先执行 `npm run build:lib`，再运行 `npm run benchmark:runtime`，由 [runtime-benchmark.mjs](../../scripts/runtime-benchmark.mjs) 对实际打包 Runtime 进行 Node/JSDOM 测量。脚本检查 1 万行关键词查询与连续翻页的字段读取次数，同时记录耗时；它不包括 VXE 渲染、浏览器绘制、网络或后台，不作为端到端性能承诺。当前数字与最终门禁后复测以本批验收为准。

## 底部汇总与查询待提交提示

以下是现有表格模板的接入片段；可复制完整页面见[SummaryTable.vue](../03-业务模块/01-接入示例/SummaryTable.vue)。

```vue
<BusinessTable :columns="columns" :data="rows"
  :presentation="{appearance:{summaryEnabled:true,summaryColumn:'amount'}}">
  <template #summary="{total, summary}">
    共 {{total}} 条 <SummaryResult :summary="summary" />
  </template>
</BusinessTable>
```

从包根入口或 `@company/business-table/components` 导入 `SummaryResult` 与 `SearchPendingIndicator`。`SummaryState` 同入口提供类型；Headless 使用 `runtime.summary.value`，状态为 disabled/loading/ready/error。`value` 为未格式化的精确十进制字符串，`text` 为列数字规则生成的显示值，`scope` 区分 query/selected。读取完整查询复用 readRows/readAll 的限制，缺少能力、无效数值及读取失败显示错误；null/空值跳过。选择记录时改为所选合计；关闭开关隐藏并取消请求。此版本仅支持一个数值列的 sum，不提供服务端聚合接口。

自定义搜索按钮可写 `<SearchPendingIndicator :pending="context.pending" />`。圆点反映草稿与已提交条件差异，改回原值或成功提交会清除；非法输入不提交。数据请求错误由加载错误区域表达，不复用待提交状态。外部筛选按钮应使用已应用列筛选/组合筛选状态，不把未提交草稿当已启用。
