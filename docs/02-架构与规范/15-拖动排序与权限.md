# 拖动排序与权限

拖动排序由共享 UI 层 [useDragReorder](../../src/ui/useDragReorder.ts) 接入 SortableJS。列设置、排序规则、操作按钮、页面／表格工具、视图和导出字段使用同一套指针反馈；各 Feature 保留原有排序命令、键盘移动入口及保存规则。

## 状态和职责

- SortableJS 负责鼠标／触摸手势、拖动影像、边缘自动滚动及位置过渡。触摸在拖动把手上短按住后开始，列表其他区域保留普通滚动。
- `useDragReorder` 只保存当前拖动来源、插入边缘和当前列表的 DOM 快照。它不保存业务顺序、Preference 或 View。
- `ids()` 提供全部已显示稳定 ID，包含锁定位置的项目；`disabled()`、`canMove(id)`、`canDrop(id, targetId)` 提供当前可用性；`move(id, targetId)` 继续调用 Feature 自己的受保护命令。
- `setList` 绑定包含排序行的真实 DOM 容器，`row(id)` 绑定行，`handle(id)` 绑定把手。标题等非排序节点可以与行共存。每个工具分组、表格实例和面板拥有独立 Sortable 实例。

```vue
<div :ref="reorder.setList">
  <div v-for="item in items" :key="item.id" v-bind="reorder.row(item.id)">
    <button type="button" v-bind="reorder.handle(item.id)">拖动</button>
    <!-- 保留 Feature 已有的上移／下移按钮。 -->
  </div>
</div>
```

## 插入和提交

拖动中显示前／后蓝色插入线和拖动影像，当前数据顺序保持原样。鼠标或手指位于目标上半行时表示插入到目标之前，下半行表示之后；自身、相邻未改变位置、其他列表和不可到达的边缘不显示有效线。

松开时重新读取当前权限与落点，先恢复引擎可能改动的 DOM（包括 Vue 片段锚点和非排序节点），再调用 `move`。Vue 完成数据驱动的更新后播放短位置过渡；系统开启减少动态效果时关闭过渡。只有 Feature 的合法命令可以改变顺序，DOM 的临时位置不进入持久化。

锁定项目保留完整列表中的原槽位。共享层先在可移动项目中计算目标，再将结果投回完整列表，只有实际结果能紧邻插入线表示的边缘时才允许松开提交。

## 取消和失败路径

Escape、原生拖动取消、离开有效列表、稳定 ID／权限槽位变化及面板卸载会清理插入线。当前手势取消或卸载时结束 Sortable 的拖动生命周期，移除影像、监听器和滚动计时器。一次拖动不会在另一个具有相同 ID 的列表中生效。

`move` 沿用各 Feature 的错误处理与事务边界：设置列表修改草稿，应用后才进入正式表；视图由 Views Runtime 完成保存与失败恢复；导出列表只改变当前导出配置。拖动结束前已恢复 DOM 并清理瞬态，即使命令拒绝或异步持久化失败也不会留下引擎顺序。

## 验证边界

[共享层测试](../../tests/drag-reorder.spec.ts) 检查实际 Sortable 实例生命周期、提交前 DOM 恢复、前后插入、锁定槽位、同步权限变化、稳定 ID 变化和列表隔离。浏览器手势用例见 [settings-refinement](../../tests/e2e/settings-refinement.spec.ts)，覆盖真实鼠标、触摸影像、取消与边缘滚动。实际执行结果记入本批验收；本地浏览器结果不替代业务后台权限和持久化接口验收。
