# 配置来源诊断

`explainConfiguration` 用于排查某列宽度、分页或外观为何取这个值。它显式解析传入快照，复用同一套合法性检查和权限约束，不保存或修改用户设置。

```ts
import {explainConfiguration} from '@company/business-table'

const explanation = explainConfiguration({definition,remoteOverride,preference,viewColumns})
const width = explanation.entries.find(entry => entry.path === '/columns/name/width')
console.log(width?.source, width?.effectiveValue, width?.history)
```

这是调用片段，输入结构与 `resolveConfiguration` 相同。ConfiguredBusinessTable 的组件引用还提供 `explainConfiguration(viewColumns?)`，使用当时 props 中的 definition/remoteOverride/preference；需要视图列覆盖时显式传入。

## 返回结果

| 字段 | 说明 |
| --- | --- |
| `scope` | 固定 supplied-snapshot，表明这是给定输入的解析结果 |
| `coverage` | columns、pagination、presentation |
| `resolved` | 与普通 resolveConfiguration 相同的有效配置与 diagnostics |
| `entries[].path` | RFC 6901 JSON Pointer，稳定 ID 中的 `/` 和 `~` 会转义 |
| `source` | declaration/default/remote/preference/view，尚无合法生效值时为 null |
| `effectiveValue` | 实际生效的规范化值；无合法值时 undefined |
| `history` | 各层 accepted/rejected/ignored 记录、规范化值及拒绝/省略原因 |

`declaration` 表示本地声明，`default` 包括平台默认值及列的 `default`。同值的合法覆盖仍可标明来源；非法字段、身份不匹配、越权覆盖记录为拒绝。`history.value` 只包含合法归一化值，不复制被拒绝的原始输入。偏好差量省略的等于默认值字段记录为 ignored；派生值可以通过 `history[].derivedFrom` 指向它所依据的字段。列顺序的 `history.value` 保留合法请求位置，`effectiveValue` 为锚定不可移动列后的最终位置。

## 边界

该结果不自动追踪 Runtime 后续本地编辑、持久化响应或当前视图。列诊断覆盖解析器校验的字段、能力与顺序，不复制 renderer 等可信本地扩展函数。Feature Gate、settings 权限页、业务 DataSource 和渲染配置不在 coverage 内；排查这些字段请使用其现有诊断及调用方输入。这里没有配置 Inspector 页面，也没有设置历史。

普通 `resolveConfiguration` 不构建解释记录。只在诊断操作中调用 explainConfiguration，避免每帧生成大对象。诊断可能包含业务定义和偏好值，不应无差别写入远程日志；按需要摘取字段。
