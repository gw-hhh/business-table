# 本地运行与接入

## 本地运行

Windows 可双击仓库根目录的 [start-demo.cmd](../../start-demo.cmd)。保持命令窗口打开，访问它显示的本地地址；通常是 http://127.0.0.1:5173/ 。修改源码后开发服务自动刷新，端口占用时以实际提示为准。

```bash
npx pnpm@10.17.1 install --frozen-lockfile
npx pnpm@10.17.1 run dev -- --host 127.0.0.1
```

首次执行浏览器测试前安装 Chromium：`npx pnpm@10.17.1 exec playwright install chromium`。完整检查为 `npm run verify:release`，文档单独检查为 `npm run audit:docs`。

## 组件接入

简单页面传 `data`；服务端分页传 `dataSource.query(query)`。列使用稳定 `id` 保存配置。支持列显隐、列宽、左右冻结、排序、数字/货币/百分比、值映射、视图和行操作。`Persistence` 可接 LocalStorage 或后端数据库 API。Windows 运行 `verify-release.cmd`，CI 在 development/main push 与 PR 时执行相同 release gate。

## Provider 查询

组件每次发起查询都会取消上一次的 `query.signal`。适配器应把它传给请求客户端，例如 `fetch(url, { signal: query.signal })`。即使适配器暂时不支持取消，组件也只接受最新请求的结果、错误和 loading 状态；卸载、替换 Provider 或切回本地 data 后，旧结果不会写回。

`queryChange` 事件和 Provider 各自收到独立的查询快照，筛选值使用可结构化克隆的数据（例如字符串、数字、日期、数组和普通对象）。两者修改参数不会改变组件内部查询或输入 View。当前请求失败时保留上一次显示的数据，并提供错误提示；点击刷新可重试。

## 分页与加载

搜索、排序、切换 View 和修改每页条数都会回到第 1 页，每次操作只发起一次查询。本地数据减少时页码收敛到最后有效页，空数据使用第 1 / 1 页。远程返回的 total 如果使当前页越界，组件会自动补查最后有效页。

组件内置加载提示与 `aria-busy`，不要求宿主额外注册 VXE Loading 组件。表格默认使用内容自然高度；`fill` 模式占满有确定高度的父容器，由表格内部滚动并保持表头固定。虚拟滚动需要另行设计和验证；不能在无确定高度的父容器中使用 VXE `height="auto"`。

宿主重新渲染时，即使重新创建 pagination 对象或 pageSizeOptions 数组，只要分页默认值和可选项内容相同，组件会保留当前分页与已应用设置。实际改变默认每页条数或允许范围时，才按新配置重新校验。

## 选择全部结果与查询区偏好

开启 `selection` 后，`await table.selectQuery()` 选择当前查询的全部结果，`table.getSelectedRows()` 返回原始行。组件引用和 Runtime 提供同一个命令。远程数据源需实现 `readAll`，并传递收到的 `signal`；最多读取 10000 条，接口缺失或失败不会改动原选择。修改查询、表格、数据源、选择开关或手动选择，会使正在读取的旧选择请求失效；卸载后也不再写回。

查询区显示和展开可独立保存，避免在页面上增加一组持久化 watcher：

```ts
import { useTableControls } from '@company/business-table'

const controls = useTableControls({}, {
  persistence: {
    load: () => localStorage.getItem('tenant.user.assets.controls'),
    save: value => localStorage.setItem('tenant.user.assets.controls', JSON.stringify(value)),
  },
  onError: cause => reportPreferenceError(cause),
})
```

在组件 setup 中调用，并将 `controls.advanced`、`controls.searchVisible`、`controls.selectionVisible` 绑定到对应界面。适配器可不提供；提供后只保存 advanced/searchVisible 两个 boolean，不保存临时多选栏。读取坏数据回到传入的初始值，存储不可用仍可操作。键需按用户和页面隔离，不与命名 View 共用。

## 设置与工具

先开启 `features.columnSettings`，再声明需要的设置：直接 `BusinessTable` 使用 `settingsDefinition`，`ConfiguredBusinessTable` 使用 `definition.settings`。设置页由 pages 声明，列模块由 columnSections 声明，具体可配置字段由 column.configurable 声明；列设置取三层交集。

未配置、false、enabled:false 或 visible:false 都隐藏。true 表示显示并允许修改；`{enabled: true, disabled: true}` 表示显示只读。远端只能继续收窄。只读会拦截界面和设置命令的写入，但保留已有合法偏好与 View 值；应用设置不会自动保存命名 View。完整示例见 [配置入口](../02-架构与规范/03-配置与能力规范.md)。

工具设置和真实按钮必须共用 `tools` 声明及 `presentation.toolbar` 布局。工具需有稳定 ID 和真实 handler；没有工具的区域不显示。报价 Demo 使用共享 ToolStrip，默认显式开放全部已实现设置；在工具栏页调整名称、顺序、位置和形式后，点击应用即可查看实际按钮变化。配置示例 `/?example=config&mode=readonly` 展示只读，`/?example=config&mode=unconfigured` 展示未配置时隐藏。

列内“试算”用于给出一个临时原值，核对显示文本、导出值与 Excel 格式，不修改业务数据。BT-08 的计算字段和公式引擎仍未实施。

## 列筛选、组合筛选与方案

筛选为显式开启的组件能力，不在默认基础表格里初始化编辑器：

```vue
<BusinessTable
  table-key="tenant-user.assets"
  :columns="columns"
  :data="rows"
  :features="{ filters: true }"
/>
```

列的 `type` 决定默认编辑器；`filterable: false` 禁用该列筛选。`column.filter` 可声明 `type`（text/number/date/single/multi/boolean）、`source`（data/mapping/manual/remote）、`operators`、`search`、`counts`、`options`。稳定 `column.id` 用于能力白名单，条件中的 `field` 对应数据字段。关闭的 Feature 不读取详情、不创建编辑器状态、不加载筛选 UI。

数字列可通过 `column.filter.inputUnit` 声明原值单位（最多 40 字，如 `元`、`件`、`kg`）。编辑器和摘要按条件保存的 `unitFactor` 显示元/千元/万元/亿元；后续修改列的显示缩放，不会改写已保存条件的输入基准或原值。单位只是显示声明，不执行额外换算，也不按业务字段名猜测分/元。

默认 UI 包含表头列筛选、组合筛选、条件标签和方案管理；组合抽屉标题区“筛选方案”打开独立管理窗口，载入方案只改草稿，点击“应用条件”才更新查询。也支持 `filters: { enabled: true, mode: 'custom' }` 配合 `filters` slot，或者 `mode: 'headless'` 后通过 `activateFeature('filters')` 取得 `FiltersContext`。`openFilters(columnId?)` 打开列或组合编辑器；`setFilterState({ columnFilters, filterGroup })` 作为受校验的 Runtime 命令，不需要在业务页面另存一份正式筛选状态。

基础查询、列条件与组合条件互相独立，最终同时生效。`Query.filters` 包含手动基础条件和 Search Feature 投影出的条件；`Query.columnFilters` 单独保存列筛选条件，Provider 需要将两者各执行一次。`Query.filterGroup` 是递归 `{ logic: 'and' | 'or', rules: (FilterConfig | FilterGroup)[] }`，服务端需按组逻辑处理，并对字段、操作符和访问权限再次验证。金额/百分比条件中的 value 已转换为原值，不要根据显示格式重复换算。

候选项优先使用 `DataSource.options(column, query, { search, signal, values? })`；手工/映射源直接按配置取值。数据源没有 `options` 时，data 源使用 `readAll(query, { limit, signal })` 读取完整数据（上限 10000），不会用当前页替代全集。`options` 返回 `{ value: string | number | boolean | null, label: string, count?: number }[]`，原值类型必须保留。

### 筛选摘要与后台值

`value` 是查询和保存的实际值，`label` 只用于显示。例如后台返回 `{ value: 1, label: 'A' }`，选择后摘要显示 A，`Query.columnFilters`、View 和筛选方案仍保存数字 1，不保存 A。`1`、`'1'`、`false`、`null` 按原始类型分别匹配。

从后台恢复 View/方案后，摘要先使用列的手工选项或映射。缺失的选项标签通过 `DataSource.options` 再查询，`values` 携带当前已选原值（如 `[1]`）；适配器应返回这些值对应的标签，即使它们不在当前页、当前搜索或候选项分页内。保留并传递 `signal`。旧适配器可以忽略新增的可选参数，但若响应不含已选项，摘要只能显示原值。接口失败或查不到标签时同样回退到原值，不改写条件，也不阻止查询。

```ts
async options(column, query, { search, signal, values }) {
  const response = await fetch('/api/table/options', {
    method: 'POST', signal,
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({ field: column.field, search, values }),
  })
  if (!response.ok) throw new Error('筛选项读取失败。')
  return response.json() // [{ value: 1, label: 'A' }]
}
```

需要合并三层条件时，在表格上声明 `query-summary`，见[统一查询摘要](../02-架构与规范/03-配置与能力规范.md#统一查询摘要)。基础搜索的摘要使用 `SearchContext.summaryItems`（已应用值），或直接使用导出的 `SearchSummary` 组件；不要把 `SearchContext.values` 中尚未提交的草稿拼成正式摘要。单选查询预设与完整示例见 [配置入口](../02-架构与规范/03-配置与能力规范.md#搜索显示值与实际值)。

有 tableKey 时默认按表格隔离保存在 LocalStorage；需要账号隔离时使用包含租户与用户范围的 tableKey，或传入业务适配器。`filter-plan-persistence` 同时支持 BusinessTable 与 ConfiguredBusinessTable，传 `null` 隐藏方案管理，只保留筛选：

```ts
import type { FilterPlanPersistence, FilterPlansEnvelope } from '@company/business-table'

const filterPlanPersistence: FilterPlanPersistence = {
  async load(tableKey, options) {
    const response = await fetch(`/api/table/filter-plans?key=${encodeURIComponent(tableKey)}`, {
      signal: options?.signal,
    })
    if (!response.ok) throw new Error('筛选方案读取失败，请重试。')
    return await response.json() as FilterPlansEnvelope | null
  },
  async save(tableKey, value) {
    const response = await fetch(`/api/table/filter-plans?key=${encodeURIComponent(tableKey)}`, {
      method: 'PUT', headers: { 'Content-Type': 'application/json' }, body: JSON.stringify(value),
    })
    if (!response.ok) throw new Error('筛选方案保存失败，请重试。')
  },
}
```

适配器存储完整 `FilterPlansEnvelope`；读取返回 null 表示暂无方案。读取失败不会被当作空数据覆盖保存；保存失败不会关闭编辑窗口。后端还需处理账号鉴权以及多客户端版本冲突，不能把前端写队列作为跨客户端互斥。

本次验证范围及未完成的完整迁移项见 [docs/06-验收记录/2026-09/2026-09-23-筛选系统迁移/README.md](../06-验收记录/2026-09/2026-09-23-筛选系统迁移/README.md)。

## 数据工具

`features` 中分别开启 `conditionalFormatting`、`grouping`、`compare`、`rangeSelection`，再提供同名定义属性。默认关闭；开启后界面按交互加载。条件标记即使未打开抽屉，也会按已保存规则标记行。分组和对比读取当前完整查询；远程适配器需实现 `DataSource.readAll`，接口缺失时明确报错。区域选择仅处理当前页的可见数据列，不保存选区。

配置字段、`allowedItems`、只读、View/Preference 优先级及 `ConfiguredBusinessTable.savePreference` 的异步保存边界见[数据工具接入与行为](../02-架构与规范/07-数据工具接入与行为.md)。四项工具的真实后台与旧版视觉验收以[本批验收](../06-验收记录/2026-09/2026-09-23-剩余数据工具对齐/README.md)为准。


## 视图、导出与模板

`createViewsRuntime({tableKey,initial,apply,save})` 与 `ViewsPanel` 提供共用视图命令/UI；保存 Promise 成功后才发布状态。`isSystem` 视图不可改名/删除，应用时清空查询且保留当前布局。`isReadOnly` 限制修改；远程权限和并发版本仍由业务持久化接口负责。

`ExportDialog` 接收固定业务 `fields`（稳定 id、标准 label、有效 ColumnConfig、可选 total）和当前查询/当前页/所选等 `groups`。使用 `appearance` 继承表格字体、颜色、对齐，再由列设置覆盖。显示值通过统一 `evaluateCell` 生成；`raw` 保留原值，`both` 分列输出。`presets/savePresets` 负责独立方案存储。大型远程数据使用服务端导出，浏览器范围读取最多 10000 条。

`TemplateDownloadDialog` 接收固定 `TemplateDefinition`，字段可配置说明及 choices；个人列标题/顺序/隐藏不会改动导入模板。空白模板有填写与说明工作表，带示例模板另加示例工作表，填写区不混入示例。

`useSearchShortcut(focus)` 在非输入、非模态弹窗区域把 `/` 交给宿主焦点回调；Headless 页面可恢复查询区并定位自己的输入框。查询区展开/隐藏偏好可通过 `useTableControls` 的独立 persistence 适配器保存。


## 自定义与 Headless 筛选方案

`FiltersContext.plans` 提供只读 plans/loading/ready，以及 load、save、rename、remove；无持久化时为 undefined。稳定 tableKey 默认使用本地适配器，也可传 `filterPlanPersistence` 对接后台，传 null 关闭方案能力。首次使用先等待 `plans.load()`。`context.readPlan(id)` 返回通过当前字段能力检查的 FilterState 副本；自定义 UI 可以先放入草稿，用户确认后调用 `context.apply(state)`。

方案仅保存 `columnFilters` 与 `filterGroup`，基础查询属于 View 的 `search.values`。默认、Custom、Headless 共用同一个方案 Runtime；关闭编辑器保留方案，Feature 撤销、表格换 key 或卸载时释放并拒绝旧命令。存储失败不发布新方案，也不改变已应用查询；读取失败后需重试成功才允许写入。
