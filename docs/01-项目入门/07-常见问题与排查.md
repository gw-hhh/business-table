# 常见问题与排查

先确定正在使用 `BusinessTable` 还是 `ConfiguredBusinessTable`，再查对应配置路径。完整字段表见[配置手册](../02-架构与规范/08-配置字段手册.md)，本地调试从[操作教程](05-使用操作教程.md)开始。

## 入口或控件不显示

| 现象 | 按顺序检查 |
| --- | --- |
| 没有列设置入口 | features.columnSettings → settings.pages 至少一个可见页 → mode 是否 headless → 远端是否关闭 |
| 只有基本，没有映射/模板等 | pages.columns → columnSections.mapping/template → 当前列 configurable.mapping/template |
| 没有数字模块 | 列 type 是否 number/currency/percent → columnSections.number → configurable.format |
| 想只读却隐藏了 | 不要用 false；使用 `{ enabled: true, disabled: true }`，并保证父级已声明 |
| 工具栏区域消失 | tools 是否为空、visible:false、没有 handler、空子菜单；正常空区域应隐藏 |
| 行动作没有出现 | 本地功能、allowedItems、Registry 中注册 ID、visible 谓词；不能只配置一个 label |
| 数据工具没出现 | 对应 features 是否开启、entry 是否 false、远端是否关闭 |

设置 `visible:false` 只是不显示界面，不代表后端已隐藏字段数据。后台权限需要单独控制数据返回和动作执行。

## 修改后没有生效或不能应用

- 先区分编辑草稿与正式应用；调整滑条后仍需“应用”。无效数字可能在其他页签，检查错误提示并修正或恢复相应分组。
- 父级/模块/列能力显式 disabled 时只能查看；页面改按钮 disabled 属性不能绕过 Runtime 守卫。
- 列宽受 min/max、冻结受 allowedValues 限制；每页条数必须属于 pageSizeOptions。
- 当前命名 View 可能覆盖个人基准；设置应用不会自动覆盖同名 View，按需要更新视图。
- 渲染列可分配额外空白宽度，配置 160px 不代表任何容器下量到的 DOM 宽度都恰好 160px。

## 刷新后设置丢了

1. 直接入口是否传了 persistence？仅 tableKey 不自动保存普通列设置。
2. 配置入口是否传 savePreference，并在下次进入时真正读取 preference？只打印 preferenceChange 不会写入后台。
3. 是否点击了应用、保存成功？浏览器存储可能被禁用或达到配额。
4. tableKey/用户范围/列 ID 是否改变？旧 ID 不再匹配会被忽略。
5. 是否把命名视图、筛选方案、个人偏好写进同一个存储键？应分开保存。

配置示例 `/?example=config` 仅显示偏好差量，刷新不会自动恢复该差量；可运行文档中的 ConfiguredTable 保存示例。避免用清空所有 localStorage 处理问题，先备份并定位当前表格的键。

## 查询、摘要或数据范围不正确

| 现象 | 检查 |
| --- | --- |
| 选 A，后台收到错误值 | options.value 应为实际值，label 才是 A；不要全转字符串 |
| 恢复视图只显示数字 | options 是否响应 values 回查，返回类型是否与保存值一致 |
| 列筛选/组合条件不起效 | 后台是否执行 columnFilters/filterGroup，而不只是 filters |
| 修改搜索没查询 | Search.setValue 修改草稿；还需 submit |
| 清空后默认条件又回来 | resetBehavior=default 会恢复默认；需要空条件时使用 empty |
| 数据只有当前页却显示“全部” | 是否误把服务端当前页传成 data；完整读取是否实现 readAll |
| 旧结果覆盖新结果 | DataSource 对象是否稳定，是否绕过 Runtime 另行请求并写数据 |
| 一次操作发两次相同请求 | 不要同时使用 dataSource 和在 queryChange 再请求一遍 |
| 金额多乘了一万元/100 | 后台收到的条件 value 已是原值，不重复使用 unitFactor 换算 |
| 分组/对比/全选失败 | 远程 readAll 是否可用、是否超 10000、是否真实返回完整集合 |

协议和联调清单见[后台对接](../02-架构与规范/09-查询与后台对接.md)。

## 自定义界面、样式与方法

- 样式缺失：检查 `@company/business-table/style.css`、VXE 注册及宿主全局 CSS 覆盖；先运行最小示例排除页面样式影响。
- fill 高度异常：父容器需要确定高度，Flex 容器还需合理的 min-height；不要只给表格 fill 而让父级完全依内容撑开。
- activateFeature 没有上下文：功能可能关闭、尚未挂载或受设置策略过滤。先等组件挂载，再 await 激活；不要复制内部状态作替代。
- 配置入口调用 viewSnapshot/applyView 报错：该入口未公开这些方法；使用 BusinessTable 的对应入口，详见[配置手册](../02-架构与规范/08-配置字段手册.md#公共事件与命令)。
- Search 自定义表单不参与视图：是否通过 context.setValue/submit，而不是私有 ref 直接拼接 Query？搜索项 ID 是否稳定？
- 预览/导出与自定义 renderer 不同：renderer 是业务 VNode；共享导出解释由 ColumnConfig 控制，不会执行任意 DOM/模板脚本。

## 收集诊断信息

监听组件 `diagnostic`，记录 code、path、message，以及当前构建提交和配置来源。常见 code：ConfigParseError（坏 JSON）、SchemaValidationError（字段或范围无效）、CapabilityViolation（能力限制）、UnknownRegistryId（未注册 ID）。Registry 可通过 `createRegistry({ onDiagnostic })` 单独接收注册与解析诊断。

查询失败目前写入表格错误状态，不通过 diagnostic 自动发送 DataSourceError；该名称虽在诊断类型中声明，也不能据此假设有实际事件。排查查询失败时查看表格提示、网络状态和响应，或在自己的 DataSource 适配器中记录后继续抛错。

提交问题时提供：当前分支/提交、使用入口、最小配置、操作步骤、预期与实际、控制台和接口状态；业务记录与账号信息按必要范围脱敏。不要仅发测试数量说明某个视觉/后台问题已经排除。

## 当前不应期待的能力

没有设置历史；规则试算不是公式引擎；下载模板不是 Excel 导入；本地存储不是跨设备同步；前端 disabled 不是后台授权；本地写队列不是多客户端版本冲突方案。未完成路线见[后续路线图](04-后续路线图.md)。
