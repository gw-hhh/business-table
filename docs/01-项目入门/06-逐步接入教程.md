# 逐步接入教程

本教程按“先显示数据，再开放能力，再接后台”组织。示例都使用公开包导出；完整文件见[接入示例](../03-业务模块/01-接入示例/README.md)。仓库名是 business-table，当前包名是 `@company/business-table`，不能据此假定已发布到公共 npm。

## 在当前仓库体验

先执行[本地运行步骤](02-本地运行与接入.md)，打开 `/?example=config`。这是最快的体验路径，不需要打包或安装另一份组件。

## 在另一个 Vue 项目使用

在本仓库执行：

```bash
npx pnpm@10.17.1 install --frozen-lockfile
npm run build:lib
npm pack
```

`npm pack` 打印实际 `.tgz` 文件名。复制该文件到目标 Vue 3 + TypeScript 项目，再执行 `npm install ./实际文件名.tgz`；目标工程同时安装满足 package.json peer 范围的 Vue 和 VXE Table。当前范围为 Vue `>=3.5.43 <4`、VXE Table `>=4.21.10 <5`，构建 Node 要求见仓库 [package.json](../../package.json)。本地包包含 docs、声明、JS 与 CSS；不是复制 Demo 作为平台源码。

目标应用 `main.ts`：

```ts
import { createApp } from 'vue'
import BusinessTablePlugin from '@company/business-table'
import '@company/business-table/style.css'
import App from './App.vue'

createApp(App).use(BusinessTablePlugin).mount('#app')
```

插件注册 VXE 和两个表格组件；按组件导入时也应完成 VXE 注册并加载样式。第一次接入建议采用上面的插件路径，避免漏掉底层表格依赖。

## 第一步：本地数据

复制 [assets.ts](../03-业务模块/01-接入示例/assets.ts) 与 [MinimalTable.vue](../03-业务模块/01-接入示例/MinimalTable.vue)，在 App 中使用后者。

- `row-key` 指向行唯一字段，样例为 `id`；每行值必须稳定且唯一。
- `column.id` 标识保存配置的那一列；`field` 指向业务数据。改标题不应改变 ID。
- `data` 是完整本地集合，组件执行本地筛选、排序和分页。已经服务端分页的数据应走 `dataSource`。
- `width` 是基准宽度；有剩余空间时渲染列可按布局分配空间。不要把 DOM 宽度当作保存的配置宽度。

此时已经有基础表格，不会自动出现全部设置。

## 第二步：选择配置入口

| 需求 | 入口 | 配置位置 |
| --- | --- | --- |
| 简单页面，本地字段直接传入 | `BusinessTable` | `columns`、`features`、`settingsDefinition`、`presentation` |
| 代码定义 + 后台收窄 + 用户差量 | `ConfiguredBusinessTable` | `definition`、`remoteOverride`、`preference`、`registry` |

两者共用 Runtime；配置入口在外层处理定义和差量。**不要混用保存协议**：直接入口的 `Persistence` 保存 `TableConfig`，配置入口的 `savePreference` 保存 `PreferenceV3`。详见[持久化指南](../02-架构与规范/10-偏好与视图持久化.md)。

复制 [ConfiguredTable.vue](../03-业务模块/01-接入示例/ConfiguredTable.vue) 可一次查看完整组合：

1. `definition.features` 开启功能。
2. `definition.settings.pages` 声明设置页。
3. `definition.settings.columnSections` 声明列内模块。
4. 每列 `configurable` 声明可修改的字段及宽度范围。
5. `registry.register('rowAction', 'view', ...)` 注册真实动作，`allowedItems` 允许显示。
6. 读取偏好后再显示可编辑表格；`savePreference` 等待写入成功，`preferenceChange` 接收已提交值。

这是“全部已实现设置开放”的教学示例。生产页面可以只保留需要的声明，未声明项隐藏；只读使用 `{ enabled: true, disabled: true }`。字段表见[配置手册](../02-架构与规范/08-配置字段手册.md)。

## 第三步：自定义界面

[CustomSearch.vue](../03-业务模块/01-接入示例/CustomSearch.vue) 展示 `mode: 'custom'`：使用 Search Context 的 `values`、`setValue`、`submit`、`reset`，保留统一摘要与视图生命周期。

Headless 模式适合由页面完全安排布局：搜索可从 `#before="{ search }"` 获取上下文；按交互加载的设置/筛选可先 `await table.activateFeature(name)`。只替换界面，不在 App 中另造正式查询或设置状态。更多边界见[配置规范](../02-架构与规范/03-配置与能力规范.md)。

## 第四步：连接后台

复制 [asset-source.ts](../03-业务模块/01-接入示例/asset-source.ts) 和 [RemoteTable.vue](../03-业务模块/01-接入示例/RemoteTable.vue)，将路由改为业务接口，并按[查询与后台对接](../02-架构与规范/09-查询与后台对接.md)实现协议。

`query` 返回 `{ rows, total }`；`total` 是筛选后的完整总数。`readAll` 用于全查询选择、报告及导出等完整结果读取。`options` 返回原值、标签和可选计数。三者的取消信号都要传给请求客户端。仓库没有提供示例 URL 对应的后台服务。

## 第五步：增加视图和输出

- [ViewsTable.vue](../03-业务模块/01-接入示例/ViewsTable.vue)：使用公共 Views Runtime/Panel 保存命名视图；读取失败不当空集合覆盖。
- [ExportTable.vue](../03-业务模块/01-接入示例/ExportTable.vue)：读取当前查询，再进入公共导出窗口；固定模板独立下载。
- 四项数据工具已在 ConfiguredTable 中声明，配置细节见[数据工具规范](../02-架构与规范/07-数据工具接入与行为.md)。

## 接入后的自查

- 编译通过，表格有样式，行键和列 ID 不重复。
- 未配置入口隐藏，只读项显示且不能写；动作具有真实 handler。
- 后台收到原始类型的条件，取消/乱序请求不会覆盖新结果。
- 保存失败保留可恢复界面，刷新后读取到正确账号的配置。
- 组合条件、排序、视图、导出范围在真实后台得到同样结果。

平台门禁见[测试规范](../02-架构与规范/06-测试与验收规范.md)；目标项目仍需执行自己的接口、权限和业务验收。
