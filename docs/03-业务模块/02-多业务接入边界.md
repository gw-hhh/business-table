# 多业务接入边界

BusinessTable 接收业务定义和数据，不预设报价字段。最简页面只传列与行；完整页面使用稳定 `tableKey`、Definition、DataSource、可选 Remote Override、Preference、View、Registry 和业务 handler。调用示例与接口说明见[本地运行与接入](../01-项目入门/02-本地运行与接入.md)，配置优先级见[配置与能力规范](../02-架构与规范/03-配置与能力规范.md)。

## 谁负责什么

| 平台负责 | 接入业务负责 |
| --- | --- |
| 表格、查询与分页生命周期、并发取消、加载/错误/空状态。 | 业务数据接口、字段含义、金额及日期等领域规则；远端按收到的 Query 执行完整筛选、排序和分页。 |
| Feature Gate、配置校验/迁移、列能力守卫、设置草稿与视图状态。 | 后台计算当前用户可用的 Definition/能力，服务端再次校验访问和操作权限。 |
| 通用搜索、列筛选、工具、行操作、导出和模板入口与默认界面。 | 提供稳定字段/动作/工具 ID、真实 handler、选项来源、固定模板字段和大数据服务端导出。 |
| 自有 Preference/View 协议及可替换持久化接口。 | 按租户、用户和页面隔离 `tableKey` 或持久化适配器；处理服务端版本冲突、权限和审计。 |

配置中的标题和显示顺序可以改变，`column.id`、`action.id`、`tool.id` 与业务数据字段的映射要稳定。数据接口返回的字段不自动成为表格列；操作所需的隐藏字段可继续存在于行数据中。后台配置是数据，不能保存可执行代码或 VXE 内部对象。远端只能在本地开启和能力允许的范围内收窄；关闭的 Feature 不读取详情、不初始化、不加载界面。

## 第二组业务数据示例

[ConfigExample.vue](../../demo/ConfigExample.vue) 使用两条物料数据（编号、名称、状态、金额）和独立 `configuration.example` Definition。它展示最简入口、全部设置、只读、未配置、自定义、Headless 和后台关闭模式；行操作由该示例自己的 Registry 注册，没有报价 handler。对应的[浏览器用例](../../tests/e2e/configuration.spec.ts)覆盖这些入口和配置状态。

这证明相同组件接口可以配置另一组字段与能力；它仍是仓库内的本地示例，不能据此宣称真实第二业务系统的后端、权限、远端持久化或部署已经验收。接入新系统时，应以该系统真实 API 和服务端权限再验证 Provider 查询、选项全集、用户隔离、冲突处理与大数据输出。不要把[报价演示](01-报价演示模块.md)的状态字典、金额规则或本地仓库复制进平台 Core。

日常实现先在本地完成[完整验证](../02-架构与规范/06-测试与验收规范.md)，再按用户授权推送；保留 `main`、`development` 分支，优先在 `development` 开发，默认不建 feature 分支、不自动合入 `main`。视觉改动仍需用户体验验收。
